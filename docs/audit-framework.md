# Framework documentation fact audit

This audit checks `src/content/docs.ts` (all sections except the separately audited Native Rust and Performance sections) and `src/content/framework.ts` against the **installed, downloadable `@zap-js/client@0.3.0` package**. It does not assume that a newer sibling checkout or public GitHub branch matches the website's archive.

Unless stated otherwise, implementation paths in the table are relative to `node_modules/@zap-js/client/dist/`. Line numbers identify the implementation examined, rather than another document repeating the claim. Package availability and current Vercel platform documentation are checked in the parent website audit; native examples and measurements have separate audit reports.

## Corrections made

- The download is a built package archive, not a complete framework source checkout. Quick Start no longer implies that downloading it requires building the framework. The introduction identifies the archive as the version these docs describe and warns that npm/public GitHub can expose the older architecture.
- Distinguished the Node HTTP bridge from the Vercel artifact packager.
- Documented synchronous page props, repeated query parameters, layout parameter scope, and route-discovery exclusions explicitly.
- Documented that prerendered content is selected by pathname and does not vary its server output by query string. Omitted dynamic static parameters still fall back to request-time rendering.
- Distinguished route-handler cache policy from the private/no-store page-rendering default. Applications must set private response headers themselves for personalized HTTP routes.
- Scoped the body limit accurately: managed Node defaults to 1 MiB, with Content-Length checked before dispatch and streamed bytes counted when consumed; a custom Node integration can configure that default. Actions independently enforce a fixed 1 MiB before decoding.
- Scoped the 8 MiB Flight cap to HTML hydration and prerender capture. Direct Flight navigation does not have that cap in this implementation.
- Clarified cache ownership: namespace versioning is the application's responsibility, Redis adapters enforce JSON validation and atomic writes, and custom stores must uphold that contract. Invalidation rejects stale writes but does not cancel a loader or change a result already returning to its caller.

## Executed checks

`node tests/native-docs.mjs` first generates the actual native declarations; `node tests/docs.mjs` fails with an explicit instruction if they are missing. The docs command compiles the actual displayed TypeScript strings into isolated fixtures with their documented file paths. This checks inter-file action imports, React useActionState typing, public framework exports, and generated native imports. The initial completed audit run compiled **22 examples**: 19 documentation blocks and all three TypeScript files in the landing-page CodeDemo. Native types came from the native audit's real release-compiled Rust examples, not handwritten declarations.

The same command executed six focused probes against the installed package: memoization argument identity (including signed zero), request-local isolation, defensive header copies, render-phase cookie mutation rejection, prerender request-metadata rejection, and missing shared-cache-backend rejection. Results are recorded in `.verification/docs-audit-tests.json`.

These are documentation/type/runtime-contract checks. They do not replace the parent task's build, hosted HTTP, browser, download/scaffold, and Fozzy acceptance checks. Likewise, source inspection of Redis's atomic Lua commands is not presented as a newly executed managed Redis service integration test.
